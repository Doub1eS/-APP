# 0.7.1 后台采集复核与修复

日期：2026-10-20。基于 DeepSeek 的 `488b9f9`，版本号 0.7.1 / versionCode 9。

## 判断与取舍

保留通知监听与常驻服务放入 `:capture` 的方案。采集只解析通知并写入本地文件队列；主进程打开时或用户点击确认操作时，导入Room。不开页面不等于没有进程：后台监听仍需要Android托管的采集进程。

先修正可靠性与状态误报，再测量内存和待机；本轮不增加无障碍，不扩展退款、红包、转账。独立进程不能保证HyperOS不清理，也不能仅凭结构推断省了多少内存。

## 复核发现及改动

| 问题 | 处理 |
| --- | --- |
| 先登记去重身份、后写队列；写入失败后重发也被忽略 | 同一文件锁中验证会话，先同步写完整事件，再提交索引；失败重放由Room去重 |
| 补充交易号只进入有限缓存，淘汰后可能重复入账 | 重复通知也把完整身份提交给Room，已确认账目的别名继续有效 |
| 页面与通知操作同时导入同一批次 | 主进程用互斥锁串行导入；取消向上传播，未完成批次保留 |
| 读取异常被当作空队列、导入期间的新计数被覆盖 | 读取失败不删除，状态采用AtomicFile；剩余数量包含新队列 |
| 坏记录一直占据旧批次，阻塞后续账目 | 保留坏行，并原子合并后续队列，正常账目继续处理 |
| 历史布尔值与通知可见性被当作活跃证据 | 匹配系统当前PID/UID/进程名，服务回调登记所属PID；常驻通知区分连接/断开 |
| 快速开关时stopService取消尚未完成的前台服务启动，采集进程崩溃 | 停止只保存设置并通知已存在实例；启动先完成前台登记，再由服务核对设置自行停止，按startId避免取消更新的启动 |
| 旧偏好迁移覆盖AtomicFile恢复的关闭状态和会话 | 主文件或可恢复备份已存在时不再执行旧偏好迁移 |
| 页面不可见仍读取状态 | 状态轮询限制在STARTED生命周期，停止时取消读取 |
| 调试广播可被普通应用调用，采集进程中的调试导入打开Room | 调试Receiver要求系统DUMP权限；DEBUG_DRAIN归默认进程；发布版没有这些Receiver |
| 自动设备测试可能误用手机 | build-local.ps1仅允许指定模拟器，直接安装与instrument，不走UTP自动卸载路径 |

所有诊断只保存固定原因、来源和时间。付款队列包含记账必需的金额、商户和时间，不保存整段通知原文或聊天内容。
