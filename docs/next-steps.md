# 练呗后续改进计划

更新：2026-10-21。此文记录已完成工作与下一步验收，不代表待办能力已经实现。

## 当前进展与计划调整

- 0.7.0（488b9f9）已把通知监听和常驻服务拆到 `:capture`；保留这个方向，UI进程负责Room，采集进程负责解析与文件队列。
- 0.7.1优先修复队列提交顺序、身份补全去重、并发导入、失败恢复、状态误报和调试入口权限。详细证据见[本轮复核](capture-v7.1-verification.md)。
- 0.8.0加入备份恢复、待确认编辑及批量处理、重复采集写入优化、失败队列管理、订阅本地提醒与筛选。验收以[0.8记录](offline-v8-verification.md)为准。
- 0.7.0文档记录了特定小米15配置下划走导致整个包被停止的现象，不能推断所有HyperOS版本和设置下划走都等于强行停止。0.8本轮在用户开启自启动并重新授权后，划走页面主进程消失，采集进程已连接且系统自检回调通过；仍不代表全过程无中断或长期保活。
- 目标是页面生命周期与采集分离；遇到系统清理整个包时，应明确告知并引导恢复。系统设置入口需要用户操作，不能称为“一键修复”；常驻通知存在也不能单独证明监听已连接。

## 核心目标

通知监听独立于界面持续工作。练呗页面打开、关闭、从最近任务划走不应影响付款采集；后台内存尽量小。系统强行停止、撤销权限等无法持续工作的状态应如实展示。不把“有通知使用权”等同于“正在监听”。

## P0：后台监听稳定性

1. 记录现有版本在划走、锁屏、重启、系统清理下的进程和监听绑定状态，区分任务移除与整个应用被停止。
2. 已完成独立采集进程与跨进程文件状态。继续验证升级迁移、进程突然退出后的队列恢复；文件操作必须保持跨进程互斥，不改用多进程SharedPreferences。
3. 在小米15验证系统绑定、断线重连、后台自启动和省电设置。必要时评估合规的持续运行方案及可见提醒，不以无障碍空服务或循环重启伪装保活。
4. 明确授权已开但服务未连接、缺少通知、正文隐藏等状态。断线期间不保证补齐历史账目。

验收：UI未打开或已划走、锁屏后，既验证监听仍连接，也验证通知实际到达；记录测试时长和必要的手机设置。不能仅凭进程存在宣布成功。

下一轮重点：锁屏长待机、重启、系统清理与强行停止分别记录；至少一次长时间待机后发出真实付款通知并核对待确认账目。划走后的短时系统自检已验证，真实付款与长时间后台仍需单独记录。

约12分钟后的ADB调试广播被HyperOS Greezer缓存，未产生新的自检时间戳；当时采集进程与系统绑定仍存在。下一轮需要分开判断“调试广播被延迟”和“真实通知回调是否受影响”，不能用旧自检时间戳宣布长待机通过。

## P0：内存与付款卡顿

1. 使用一致构建和环境测量：仅监听空闲PSS、付款事件前后增量/峰值、UI打开时总PSS、CPU与事件处理耗时。
2. 早期来源/标题过滤、有效交易后再初始化存储、限制队列和线程、合并重复事件、释放通知对象、减少诊断写入和重复正则创建。
3. 对比无线调试开/关、监听开/关，复查密码键盘前黑屏/Logo移动与卡顿；不读取密码内容。禁止将单次RSS当作独占或峰值结论。
4. 独立进程可能增加双进程同时运行的总开销，按实测决定。优化目标与预算在获得基线后确定，不预先承诺MB数。

0.8调试包已取得小米快照：页面进程不存在时，自检前后采集PSS约59–62MiB，随后5次空闲样本约45–56MiB；采集进程无Activity、SQL内存为0。后续应分析分配来源并比较优化前后相同工况，不把当前快照冒充付款峰值。

## P1：支付数据可靠性

- 通知更新、重发、交易号后补、when为0/变化、同商户同金额连续交易的去重；不以金额模糊合并而吞掉真实支出。
- 0.8已支持待确认编辑商户、金额、日期、时间、分类及批量处理；后续根据真实通知验证补全与人工修改的边界。
- 退款识别形成退款待确认，关联原消费，支持部分/全额退款并统计净支出；保留购买和退款记录。
- 红包/转账独立定义支出、收入、领取、退回的状态和统计口径，获得真实系统通知样本后再决定支持范围。
- 支付宝与更多微信通知格式、通知隐藏及权限被撤销的真机回归。

## P2：体验和扩展

- 将自动识别状态与设置入口更清楚地展示，减少用户找不到入口的情况。
- 完善两级分类筛选、图标辨识和商户分类建议，保留用户选择。
- 0.8提供JSON导入恢复与v1–4兼容；后续可评估大照片备份的分包与流式处理，当前单文件限制64MB。
- 无障碍仅作为缺少通知时的可选采集来源另行评估；不把它当成低内存或永不清理的保证。
- 小米手环睡眠接入继续暂缓，待用户有设备后推进。

## 每轮交付

更新实现、对应测试、真机证据和限制；不上传私聊、真实账单截图、无线调试配对码、设备标识和原始通知。测试报告、APK保留本地，仓库保存代码与汇总结论。
