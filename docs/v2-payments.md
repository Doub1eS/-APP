# 第二版：支付通知待确认

默认关闭。用户在“支付待确认”中阅读用途说明、开启识别，并在系统授予通知读取权。通知发布权限单独授权；拒绝发布通知仍可使用待确认列表。

仅监听微信和支付宝包名；使用标题白名单和付款成功关键词，跳过汇总、收款、退款、转账、失败、未知格式及多金额消息。规则偏保守，可能漏识别；通知标题不构成交易真实性证明，因此所有结果均需用户确认。原始通知不保存、不上传；保存来源、商户、金额、通知时间和不可逆摘要。没有网络权限。

待确认不计入消费。确认以 Room 事务写入消费，重复点击和同一事件重放不重复入账。忽略保留去重状态。删除已入账记录后不会通过同一通知再次生成。通知时间作为记账时间，不推断实际交易发生时间。相同内容但通知标识或发布时间变化仍可能生成新的待确认条目，用户需检查。

旧版数据库通过非破坏性 1→2 迁移新增 payments 表，保留原有 records 和 categories。

## 超级岛试接入

使用小米官方 miui.focus.param、miui.focus.actions 和 miui.focus.pics 扩展；支持确认动作与普通通知回退。当前适配为实验性，未取得小米权限、未经 HyperOS 真机验证。

官方要求开发者创建应用、开通服务、提交场景方案、设置测试设备白名单、联调并通过上线验证。仅安装此 APK 不保证上岛。需配置包名 com.lianbei.daily 和实际签名。官方文档：https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2132 。协议：https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2131 。

## 真机体验步骤

1. 安装新版 APK；从首页进入支付待确认，开启并授权通知读取。
2. 授权确认提醒通知；点“生成演示待确认账目”检查普通通知操作。演示不是支付识别测试，确认后会生成可删除的演示消费。
3. 小米设备完成上述开发者开通及白名单配置后，用演示入口验证岛的显示与确认。
4. 对实际微信或支付宝付款，检查是否产生包含完整金额的系统通知。应用内服务消息不一定是系统通知，没有通知则无法识别。
5. 验证确认只入账一次、忽略不入账、关闭识别后不再新增。若漏识别，可提供脱敏后的标题及通知正文用于改进规则。

当前不读取历史账单，不使用无障碍，不自动操作支付软件，不自动入账。
