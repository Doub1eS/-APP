# 练呗订阅记录方案（已确认）

## 目标
参考用户提供的订阅应用截图，在练呗内查看订阅、下一次扣费和预计支出，保持现有绿色视觉风格与本地保存方式。

## 方案选择
- 推荐：独立订阅页，包含管理、未来扣费日历和预计支出统计。入口清晰，适合持续使用。
- 简化：消费页内增加订阅列表，开发量较少，但日历和统计入口拥挤。
- 扩展：加入优惠券权益、截图识别和服务账号同步，涉及额外系统，留待后续明确需求。

## 页面与操作
底部导航调整为“今天 / 订阅 / 回看 / 我的”。
订阅页顶部显示本月预计扣费、启用数量、未来7天扣费数量、本年预计扣费。
概览下显示彩色订阅卡片，列出名称、金额、周期、下一扣费日期；支持按扣费日期排序、筛选启用或停用。
新增和编辑字段：名称、人民币金额、分类、周期（每周、每月、每季度、每年）、首次扣费日期、备注、卡片颜色。
用户补充：每条订阅增加可选缴费链接，支持完整HTTP/HTTPS网址，卡片和日历可点击“去缴费”。交给系统打开；失败提示显示在当前屏幕底部；打开链接不代表付款成功。
支持编辑、停用、恢复和删除。停用只影响未来预测，不删除已确认消费；删除需确认。
无数据时显示添加第一条订阅入口。
页面内切换列表、日历和统计：日历点选日期查看预计扣费；统计显示选定年份的月度柱状图、选定月份的分类金额与占比，并提供可读文字数值。

## 计算口径
所有概览和图表明确标注“预计”。按实际计划扣费日期归属月份和年份，例如年度订阅120元只在扣费月份计入预计120元。
首次扣费日为周期锚点；月末不存在原日期时取该月最后一天，下次仍按原锚点计算。2月29日年付在非闰年取2月28日。
未来7天包含今天及之后6天。下一扣费日取今天或未来的首个计划日期，不代表已经实际扣费。
预测根据当前订阅设置计算，不作为历史付款凭证；停用后不再产生未来预测，恢复后按原周期计算下一日期。
提供“确认本次付款”操作，核对金额和日期后生成一条消费记录；同一订阅同一周期不得重复确认。已有付款通知记录时，用户可关联既有消费，避免重复记账。
确认记录独立保留；删除订阅保留已有消费。修改周期或金额仅改变预测，已确认消费保持原金额。

## 数据与兼容
新增订阅和付款关联表，使用Room非破坏性迁移，保留现有日常记录、类别和支付待确认数据。
JSON导出包含订阅及付款关联，更新导出版本。
本阶段到期提示在应用内呈现；系统通知提醒与实际扣款能力不在本方案内。

## 验收
验证新增、编辑、停用恢复、删除、空状态与数据持久化。
验证跨月31日、闰年、季度周期、7天边界、月度年度金额、重复确认与关联已有消费。
验证旧版数据库迁移及导出内容；模拟器验证正常与大字体界面，并提供本机可调试安装包。
