# 无手机开发工作 Implementation Plan

**Goal:** 完成用户确认的六项工作：备份恢复、待确认编辑/批量处理、采集开销优化、失败队列管理、自动化回归、订阅提醒和筛选体验。
**Architecture:** 沿用 Kotlin/Compose/Room、本地文件与独立采集进程。恢复合并而非覆盖；后台提醒用Android本地调度，通知点击打开订阅页；所有改动在模拟器验收。
**Spec:** 本线程用户“完成上述工作”及上一条六项建议；无手机连接。
**Execution:** 先提交0.7.1检查点。主代理负责备份/共享DAO集成，独立子任务并行开发后统一构建。用户已授权执行，不另设确认关卡。

## 验收边界

- 保留个人数据；导入前预览、确认后事务合并。同ID保留本机；关联冲突可解释，不能静默改绑。重复导入不重复；无效/未来版本不部分写入。
- 新备份包括记录、照片、分类、订阅、付款关联、待确认/已处理支付和去重身份；支持旧JSON v1–3。导入不改变通知授权和识别开关。
- 支付可修改金额、商户、日期、时间与分类；保存编辑不自动确认，批量确认/忽略需明确数量，金额精度和并发状态有测试。
- 优化采集需提供可复现实验，对照去重/会话/恢复不退化；模拟器数据不外推小米内存。
- 损坏行/存储失败显示数量与固定原因，可重试；丢弃需确认，不泄露通知原文、不清除正常队列。
- 订阅本地到期提醒可开关，权限未开明确提示；停用/已付不提醒，同一天重复检查不重复；通知点击定位订阅；提供全部/启用/停用/近期到期筛选与对应空状态。
- 运行单元、存储、通知、UI设备测试，生成APK、报告并提交Git。真机存活/性能与微信卡顿仍需真机验证，不在本轮假报完成。
